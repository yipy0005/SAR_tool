## Design decisions resolving the reviewed design

1. **Separate upload boundaries.** Keep `SAR_MAX_UPLOAD_BYTES` as the decoded file limit (default 5,000,000), add a JSON/base64 wire limit equal to `4 * ceil(decoded/3) + 65,536`, configure Flask to admit the wire limit, enforce the decoded limit after base64 decoding and independently on multipart uploads, and enforce the serialized UTF-8 JSON limit in `SarClient` before sending. Exact decoded boundary succeeds; decoded + 1 and wire + 1 return safe 413 responses and create no batch. JSON and multipart paths must not accidentally create a batch on rejection.
2. **One comparison snapshot boundary.** In the durable MCP comparison path, validate project/relationships, read relationships, endpoint metadata, and latest summaries, build the immutable snapshot, insert the `analysis_runs` row, and insert its audit row inside one `database.transaction` boundary. SQLite uses the existing `BEGIN IMMEDIATE`; PostgreSQL uses the existing transaction boundary/isolation. On lock/serialization/conflict failure return 409 and leave no run/audit row. The browser path remains ephemeral by default.
3. **Concrete audit linkage.** Store `audit_event_id` in the versioned comparison snapshot envelope and expose it as top-level `audit_event_id` in POST/GET and the `analysis_runs` export representation. Also retain deterministic lookup `(resource_type='analysis_run', resource_id=analysis_run_id, operation='prodrug_comparison', project_id)` for defensive readback/project isolation. CSV emits the same key inside `metadata_json`; JSON and CSV tests must prove parity.
4. **Origins.** Unsaved prodrug preview rows use `quarantined_import`; committed relationships, relationship list/export, and the relationship inputs embedded in a durable comparison use `imported`; comparison outputs/snapshots use `derived`.
5. **Selection/order.** Omitted `relationship_ids` means all eligible non-rejected relationships; an explicitly empty list, duplicates, or foreign IDs is 422/403 before mutation. Snapshot and readback order is `(prodrug_registration_id, active_registration_id, relationship_id)` and every page returns `stable_order`, `total`, `offset`, `returned`, `has_more`, and `next_offset`.
6. **Endpoint parity.** `endpoint_b` accepts the browser sentinel `none` (or omission maps to `none`); `coverage=both` requires a real B and `endpoint_a == endpoint_b` is rejected. Without B, `all`, `endpoint-a`, and `review` retain their browser meanings. `q` is trimmed, case-insensitive, and matches `registration_id` only. Canonical units are NFKC-normalized and trimmed, never silently converted. `none` is never sent as a real endpoint.
7. **URL compatibility.** Preserve current Compare keys (`endpoint_a`, `endpoint_b`, `stage`, `coverage`, `q`, `selected`) and dual-read any new aliases such as `selected_compound_id`; canonical writes use the existing keys. Implement SAR initialization in `static/production_sar.js` with project validation and deterministic precedence: valid `comparison_run_id`, then valid `relationship_id`, then `sar_mode`/endpoint defaults. Invalid/foreign state renders a safe empty/not-found marker and never falls back across projects.
8. **Pair-text grammar.** Define one versioned `PAIR_TEXT_GRAMMAR_VERSION` and use it in preview and save: UTF-8 text, delimiter chosen from the first nonblank line (tab only when it contains tab and no comma, otherwise comma), CSV quoting rules, optional first-row aliases `prodrug`, `prodrug_id`, `active`, `active_id`, optional third notes field, extra columns ignored after the third for compatibility, blank rows skipped, source lines 1-based, and trimmed case-sensitive tokens with BOM removal. Structured pairs use the same normalized row model. Save must call the same parser/validator as preview.
9. **Numeric safety.** Exact comparison requires conversion to a finite real (`math.isfinite`) with no implicit unit conversion and an explicit qualifier in `{\"=\", \"~\"}`. Nonnumeric, NaN, and ±infinity summaries remain visible as `invalid_numeric` with `delta: null`; they never produce NaN/Infinity JSON, 500s, or exact statuses. Apply the same rule to endpoint comparison and exports.
10. **Ephemeral browser versus durable MCP.** `persist` defaults to `false` for the legacy browser request; the browser explicitly sends false or continues omitting it under that documented default. MCP always sends `persist=true`, is `analyze` tier/editor-gated, and returns durable `analysis_run_id` and `audit_event_id`. Test exactly zero persisted comparison runs for browser calls and one run/audit pair for MCP calls.
11. **Real fixture gate.** Add a deterministic integration/native-smoke test for `/Users/yipy/Documents/GitHub/SAR_tool/test/CellLinePanel_pIC50s.xlsx`: profile both visible sheets, select `Aggregated_Data`, header 1/data row 2, explicitly map `Sample_ID` and `SMILES`, verify wide pIC50 mapping and source cells, retrieve every staged page, commit in a test project, build summaries, and compare only explicit `Sample_ID` pairs (never `WuXi_ID_core` or structure inference).
